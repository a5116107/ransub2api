# 区域调度业务同步

生产接线由 `RegionalSchedulerAuthority`、`SchedulerSnapshotService.ExportRegionalScheduler` 和 `RegionalSchedulerReader` 复用同一条调度流完成。配置与 mTLS 启动流程见[运行时说明](regional-scheduler-runtime.md)，实时进度见[项目状态](project/STATE.md)。本说明更新原 PR 3b 的适配阶段记录，避免将历史限制当成当前行为。

## 数据路径

1. 主站权威通过原 SQL 流记录与事务锁串行发布。账号、代理、分组、规则和可用性结果在同一个 repeatable-read 事务中读取；Ent 与原生 SQL 均绑定该事务。查询、编码或验证失败回滚，不消费新版本，也不延长旧快照。SQL 提交结果不明确时不暴露候选新包，后续从数据库版本高水位恢复，不能假设该版本未提交。
2. 可信部署配置指定桶和账号 ID 白名单。导出仅包含已分配且可调度的账号；禁用分组输出空桶。影子账号的母账号所有权不由本协议推断，存在冲突的账号投影不发布。
3. 调度文档 v2 包含完整账号、分组和每个账号的最新可用性报告。相同账号跨桶只导出一份报告；`reports: []` 表示主站已确认没有规则。漏账号、重复账号/规则/模型、错账号、空报告和缺少评估时钟均拒绝。配置了规则但尚无可用证据时保留 unknown，不能用空数组替代。
4. 完整文档通过原 AES-GCM 与受认证 HTTPS/mTLS 传输，在区域先持久化版本和密文，再原子切换视图。较旧版本、同版本重放、错误归属、过期或持久化失败不恢复旧通过。
5. 区域候选、账号详情和分组策略读取同一完整视图。OpenAI HTTP/桥接、原生 Gateway/Gemini/Antigravity 的最终发送与原生 WS 逐轮可用性终检只读本地，缺少策略直接拒绝；即使误注入主站读取器也不回源。只提供候选接口的存储不授权业务发送。
6. 可用性报告保留主站原绝对有效期，读取时计入投递与存储时间，并校验实际线路和协议能力。发布新包、读取缓存及重启不续期监测通过；新包中暂停、故障或恢复的结论替换旧视图。

## 兼容与传播边界

- 先升级接收端支持 v2 及将发布的作用域字段，再启用新发布端。解码器拒绝未知字段；同为 v2 的旧版本也会拒绝包含 Messages `thinking_mode/thinking_budget/protocol_options` 的新包，因此必须先升级接收端，再开始发布这类观测。新接收端可恢复 v1 的候选/详情，但缺少可用性策略时拒绝发送。不要把候选 ready 当成业务 ready。
- 策略传播沿现有发布与拉取间隔、完整快照寿命和时钟同步约束。断连时尚有效的快照可在其原期限内使用；快照或监测结论任一到期即拒绝。这个路径不实现跨区即时撤销或新的故障回传协议。
- 托管连接的私有摘要不进入报告 JSON。未被该区域投影明确观测的连接保持 unknown，不借用普通 HTTP 或其他连接的检测结果。
- 本协议不分配并发或资金。共享 Key、账号槽位、用户权限、订阅、区域预算和账单继续由各自原权威处理；账号白名单不能替代它们。跨区域视频查询回原节点，任务、生成额度及结算归原节点。
- 完整账号包含凭据及代理字段，只能位于加密状态和受认证内部通道。日志、普通状态 API 和验证输出不得打印 payload 或凭据。每次解码有 O(全量账号) 成本，尚无生产规模延迟改善结论。
- 回退先停接流、排空，再恢复匹配的发布/接收版本；保留持久版本下限、原规则、未确认任务与账单。不清库、不重置版本制造可用性。

## 验证边界

本地回归覆盖区域不回源、真实 HTTP 零误发、原生 WS 三种模式逐轮停调、作用域/线路/过期边界、导出失败及数据冲突。PostgreSQL 集成结合实际发布事务与加密 HTTPS 拉取，核对并发修改后的完整旧视图、后续撤销/恢复、旧包重放和重启保留停调。具体命令与结果以项目状态及决策记录为准；不替代生产混合版本、全部协议能力、资金排空或 D8/D9 验收。

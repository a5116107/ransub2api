1. 核心判断

目标是“管理员定义产品边界，程序持续证明并维护合格供应”，不是增加分数后继续手工搬账号。生产尚未完整闭环：

  1. V2面板的健康色、缓存和首Token等指标，不直接决定选路资格。质量规则、原生故障保护、人工开关分别生效。
  2. 15个账号只有9、14号开启调度，每个配置并发10。配置上限不等于实时可用容量，也不代表每个模型都有两个合格备选。
  3. 主力账号的报表估算倍率0.10、利润准入倍率1.00、下游售价倍率0.20。利润门当前关闭，直接开启会排除两个主力账号。
  4. 单题通过、整轮通过、处置完成、当前可调度是不同结论。不能用一个红绿灯代替。
  5. 随机推理题、糖果题、返回模型名及Codex/TLS客户端指纹，不单独认证真实模型。当前没有模型身份认证闭环的生产证据。

3. 监测与检测的控制边界

过去窗口的高可用率不能覆盖新故障，上次通过也不能覆盖换Key、过期或模型不一致。V2忽略错误含authentication、client_cancelled、content_policy、context_limit、group_access、model_unsupported、not_found、quota_or_balance；面板成功率不是所有请求未经筛选的成功率。

5. 用户请求如何放行、等待与切换

这是OpenAI文本主链逻辑视图，不承诺HTTP/WS/媒体内部步骤相同。归属未知按已选兼容策略透传，只拦截有证据的跨线数据；未知透传不保证换线成功。HTTP200不等于SSE完整完成，已输出后的断流不透明拼接重试。

20秒是响应头限制，不是首文本SLA或请求总上限。黏性满槽可先等120秒，重试继续耗时。诊断应合并展示“已等多久、在等什么、剩余预算、为何不切换”，而非让管理员分别猜超时。

近24小时留存日志中，无账号归属的一类503在一次查询中有503条，后一次为504条；另有A9/A14归属的502及HTTP200内错误。查询时点不同，且日志不是完整冻结请求全集，不直接相加计算失败率，也不凭状态码认定都是队列问题；需请求ID与尝试链关联后定责。

6. 倍率、利润门与报表

  • 采购声明倍率：特定Key/固定组的声明，带来源、期限、模型/服务档；不是已核对的实际结算价。
  • 准入U：利润门使用的账号倍率；开启同步时需新鲜有效单组快照并保守取值。手工值不是供应商价格证据。
  • 估算C：报表使用，缺失默认0.10；默认不能包装成已确认价格。当前报表按当前C计算，不是历史逐请求采购价快照。
  • 销售D：本次固定的销售规则，不随换账号改变；actual_cost为保存的扣费，订阅扣费也不自动等于现金收入。

实时文本利润门公式为 U ≤ D × (1 - profit_min_margin - profit_safety_buffer)。上游声明0须核对语义，404只说明元数据接口不支持；不等于模型不能用。真实采购价重构继续延期，高缓存不用于绕过既定倍率上限。

独立图片/视频、Grok媒体、count_tokens、live不直接套用此文本门；混合Responses的token计费部分仍受保护。报表查询的5分钟预算不是上游响应超时。

12.1 低心智配置与上游监控面板（提案）

2026-11-20依据生产流程图册收敛本节；以下是目标设计，不将开发分支能力视作生产生效。原28项分母和未完成验收保持。

12.1.1 业务效果与对象减法

管理员只定义“卖什么、售价多少、允许从哪里采购、采购范围与服务要求”；程序承担发现变化、验证证据、维护合格供应、保护粘性和解释异常。不是追求某个最高总分，也不是采购越便宜就放松质量。

沿用账号、Group、现有检测器与原调度器，不新建第二套库存/评分/选路实现：

  • 供应记录：账号/绑定Key、固定上游组、适配器、声明模型与共享容量身份；来源需明确批准，不能把全部普通/专用账号自动纳入。
  • 产品：现有销售Group加受管策略；固定D、允许采购桶/范围与来源、模型/协议/effort/服务档及模板版本。采购桶是供应分类，不是第二个销售组；普通/参考/受管角色明确标记。
  • 证据：原探测、业务观测和判题的有范围、有期限结果；展示投影不是新的事实库。配置地址相同不自动等于缓存域或独立供应商。
  • 人工例外：有范围/期限/操作者的额外约束。原停用、停调、权限、额度仍权威，不把程序批准变成越权放行。

自动产品普通“移出”只删除当前关联，后续合格可自动加回，不隐式建立永久排除。另行明确的“临时排除”才拥有相应约束；其到期只撤销例外，不直接授予资格。检测任务按批准供应库存而非销售关联存活，移出产品不停止复测；退役供应则停止新增检测，保留历史与在途结算。

12.1.2 一份资格解释，一个关系写入拥有者

各检测器产出各自证据，不直接竞争写同一受管产品关联；原生限流/冷却仍原位生效，旧质量规则动作需按拥有者映射迁移，不能简单停规则或删除恢复记录。程序拥有者只维护其明确拥有的关联，不改其他来源/产品或人工元数据，关系与outbox原子提交；等待后/发出前重新核对同一当前资格。

硬门在前、软排序在后：范围/成本/权限/模型与已知数据归属不合格就拒绝；合格集合内优先保留健康原线路，再用上游统一性能评分选择新会话或替代线路。高缓存不抵消模型错误或超成本；慢但仍满足产品档位的热会话不因排名轻微变化切走。持续拥塞仅在兼容、剩余总预算与迁移净收益可证明时迁移，不宣称原上游热缓存会随账号搬迁。恢复线路先接新会话/小流量，不抢回已有健康会话。

12.1.3 证据合同与独立结论

复用§8和D2.6/D3.2/D5.3合同：每项至少有实际供应身份/组证据、模型映射、协议、effort/服务档、时间范围、配置/策略版本、来源、样本/覆盖和到期时间。某维度缺失就展示该维度未知，不能用账号ID或其他模型的通过补齐。读取投影有界缓存，业务选路不逐次同步出站探测或扫全量历史SQL。

正确性/验真 答题结果、同题对照、身份参考/指纹各自结论 答对不认证身份，自报模型名不作独立基线
性能/稳定 响应头、首事件、首非空文本/语义、TPS、停顿、完整完成率 明确计时起点；硬SLO与软排序分开；200流内失败独立计数
缓存 请求命中、Token读取、可观测覆盖、cold→warm与样本 上游Key/model和本人下游Key分别统计；计费改写不冒充原始复用
容量/预算 账号与共享Key占用、排队、探测延期、剩余额度 同Key跨产品不加容量；预算延期不延长原证据期限
动作 已计划/已生效/冲突/待审核，以及操作者/拥有者 检测完成不等于动作成功；冲突须给最小恢复入口

在“完整成功率”之外保留物理尝试错误率，不将面板过滤后的成功率、进程内HTTP错误率、用户最终完成率互相替代。后台按已确认scope比较，缺独立身份或缓存域证明的严格产品保持待证据；普通兼容产品可显式选择较宽证据要求，但不显示“已验真/严格高缓存”。

独立参考池不参与被测产品的隔离动作，参考来源、凭据权限及模型/版本须可核对；不同URL或账号并不自动证明参考独立。共享同题对照只支持对应功能正确性的比较，不升级为模型身份认证。

12.1.4 统一读状态，不覆盖原保护状态

该状态机是产品×scope的读投影，不替换账号原生状态列。“承载中”另有瞬时容量，合格不保证当前空槽；未知/过期/判题系统故障不伪装成明确降智。检测因预算延期保留旧结论及原到期时间，到期后停止依赖它的严格资格。已有流式输出不自动跨上游拼接。

12.1.5 后台默认三步，日常只处理异常

复用 /admin/channel-operations 的 UpstreamChannelOperationsView.vue 为入口，沿用 UpstreamBillingRateCell、AccountPerformanceCell 和原Group表单；质量/监控/优先调度页下钻同一证据，不新增平行总览。

默认必填只涉及供应凭据、批准来源、产品销售/采购边界、模型服务档和策略模板；模板生成可解释参数，TTL/样本/高级阈值默认折叠。保存前展示已配置/会生效/待证据，无合格候选、判题循环、成本字段冲突与预算不足均有结构化原因，不能保存后才发现所有账号被排除。模板版本固定，程序更新不悄悄改现有阈值，升级模板先预览影响。

日常首页展示产品“合格数/库存数/独立故障域数/共享容量约束”、主力和备用、最老待测任务及受影响下游；未知供应商容量只显示已知上限，不宣传精确QPS。管理员只处理证据缺失、预算不足、独立参考缺失、人工冲突等例外。

每条线路展示主结论和子卡：价格、最新可用、正确性、身份、性能、缓存、容量、动作；卡上直接显示结论、原因、来源/年龄/有效期、样本和作用范围，颜色之外有文字/图标。A14实例必须能同时呈现“sol答题通过 / terra证据不足 / 旧恢复冲突 / 调度开启”，不能压成单一失败。

操作保留查看证据、补资料/独立参考、立即复检、限期排除、恢复自动、解决归属冲突。立即复检进入预算队列而非浏览器自行无限出站；恢复自动不等于强制通过。模拟请求带模型/effort/服务档/上下文与归属，只读解释候选、硬门和冷缓存风险，不发付费请求、不改粘性。

12.1.6 不同指标用不同周期，恢复不制造检测风暴

业务失败优先被动登记/合并事件；恢复探测为故障Key留预算。建议模板区间为：最新可用/故障恢复1–5分钟、倍率15–30分钟、功能质量30–120分钟、身份参考按新接入/漂移及较低频巡检；性能/缓存先用业务滚动窗口，cold→warm在接入或scope改变时补。它们是待预算预演的建议，不是修改当前生产周期或已承诺SLA。

保存时检查排队延迟、执行耗时、抖动与周期是否能落在证据期限内；容量不足显示哪些scope将延期，不把100个Key同时按一个cron全量打出。实际Token仅按上游回传usage计量，达预算后停止后续检测、在途可超额；缺usage标未计量，不当0。物理调用预算含分页、判题和重试；旧v1插件宿主计量不透明时延期自动检测，业务照常。原D8公平性/多节点/全scope验收仍开放。

# 区域共享并发运行时（默认不开放模型请求）

配置入口为 runtime.regional_concurrency_file / RUNTIME_REGIONAL_CONCURRENCY_FILE，默认为空。配置文件为严格 JSON，字段采用 Go 导出名。primary 使用主站 PostgreSQL，regional 使用区域 PostgreSQL；同一区域所有 Pod 共用数据库。辅助 Redis 不拥有 SQL 业务槽位。

- Mode: primary / regional；Instance、Epoch 必填。
- primary: PrimaryInstances 为该部署 epoch 的完整主站 Pod 名单；LegacyRedisUser 为迁移前 Redis 准入身份。可先不设 Listen，仅切换主站 SQL 准入。
- regional: Region、Endpoint、ServerPin、CAFile、CertFile、KeyFile、Targets、LifetimeSeconds 必填；Targets 是 Resource(kind/resource_id) 与 Capacity 的列表。寿命 30–3600 秒。必须 role=gateway 且设置本地 auth/scheduler 文件。
- primary 的 Listen 启用独立 mTLS 监听；Scope 固定 region、客户端证书 SHA256 pin、账号/用户/Key 范围和最大 grant/lifetime。后台控制复用既有slots、已配置资金通道和视频目录；媒体查询使用下述独立监听。

## 异地视频查询转发

可选 `VideoForward` 属于同一运行时 JSON 文件；双方都须配置，只覆盖当前主节点与一个固定区域节点。先具备迁移331/332及已就绪、未过期的后台视频目录，再开放独立媒体监听。任务生成、持久成员、终态释放及结算始终归原节点，接收节点不重新占用生成额度。不配置时保留本地归属拒绝，不自动猜测对端地址。

| `VideoForward` 字段 | 含义 |
| --- | --- |
| `Listen` | 本节点专用媒体监听地址，与公开HTTP及后台控制监听分开 |
| `Endpoint` | 固定对端的HTTPS根地址，不含用户信息、路径、查询或fragment |
| `CAFile`、`CertFile`、`KeyFile` | 显式配置CA及本节点双用途证书；叶证书须含serverAuth与clientAuth（或Any） |
| `PeerPin` | 对端叶证书DER的SHA256小写十六进制摘要，共64位；TLS1.3和CA验证仍必需 |
| `UserIDs`、`APIKeyIDs`、`AccountIDs` | 允许该peer访问的实际用户、下游Key、上游账号ID；三个列表都须非空、正值且不重复 |
| `TimeoutSeconds` | 每个节点间请求总超时，默认120秒，范围1–600秒；握手5秒、响应头15秒 |

`locate` 只核对原节点本地持久任务或保留的终态归属；`query` 再次核对并重新进入原完整认证router。六项操作为Grok状态/内容、Seedance状态/取消、MiniMax-H3状态/内容，不接受创建、编辑或扩展任务，也不接受任意URL。请求携带原下游Key供原节点重新鉴权，仅经显式配置的mTLS通道传输，不写入目录或日志；客户端IP复用接收节点已验证的安全来源，不透传原始代理头。双方数据须具有一致的用户/Key/组/账号身份，否则本地拒绝。

区域网关预览门仅在同时配置本地鉴权快照与区域资金门时，允许上述注册视频查询进入后续链路；本地快照先鉴权，随后执行分组模型、Codex客户端、子代理等策略，资金门只接受实际由原节点处理的转发，本地查询仍返回503。预览门不放行视频新建、其他协议或一般模型请求，也不调用主节点鉴权。接口按已注册路由分类，任务ID取名为`models`、`usage`或`responses`不会被当作元数据/文本入口或文本Pod路由。原节点重验选定分组、客户端策略和本地资金边界，未新增资金授权或额度转移。

当前查询协议携带策略证据版本、模型、客户端标识及子代理分类；新旧节点混用会拒绝转发而不是忽略证据。升级或回滚需统一切换并排空旧任务。**若原节点也启用了区域资金门，现有视频查询仍返回503**：查询可能在发现视频终态时触发计费，尚未接入受区域账本保障的视频结算，不能把它视作零费用放行。完成计费接入及其隔离账本验收前，应在切换资金模式前排空旧视频任务；仅接收节点放行不代表端到端可用。

迁移333允许区域账本持久记录零金额请求和分配，但仅当本节点已安装同模型、内容版本一致且各项费率全零的文本价格合同；主节点结算仍独立复验。主/区域配置的价格合同须一致；区域grant、就绪检查仍要求正额可用额度，视频价格现已有下述账本基础，运行时视频发送与零/非单位倍率分组仍未放行。升级前协调实例版本并确认迁移编号不与上游冲突。回退程序前停止新准入、核对并排空零金额在途请求与outbox；保留已完成零金额记录和333放宽后的表约束，不删除幂等或资金证据。只在隔离夹具验证过升级和旧约束回滚，生产迁移另行授权。

下载沿原接口处理，Range和必要响应头保留；MiniMax-H3合法302下载地址返回客户端，节点客户端不跟随任何跳转。目录缺失、过期、冲突、peer失联或归属重验失败返回503；不进行第二跳、任务迁移、重复生成或自动切线。取消确认本身不视为生成终结。终态凭证到期后不靠sticky恢复；原5秒循环按本权威有界清理到期凭证。

原资金账本的`Price.video`冻结单个视频规格、基础价及有理数销售倍率，分别支持MiniMax-H3按次/按秒、Grok按秒和Seedance有界终态token；文本合同内容版本保持兼容。视频预留还须提供原提交member及完整`VideoOrigin`；迁移334与现有金额预留同事务保存永久身份，`Start`后明确收到task ID才绑定，`Complete`要求该task已归属原预留。主请求与各区域对账共用主节点永久任务索引，换请求ID、member或区域也不得重复入账；原节点可通过`LoadVideoTask`恢复原预留和完整已完成事件，零价视频同样受限。

资金模式查询的账号解析现通过`ResolveVideoTaskOwner`只读取原节点SQL执行记录，槽位或sticky过期不改用其他账号；来源缺失/损坏或转发证明不一致则拒绝，主节点持有区域结算记录也不取得执行归属。原查询准备函数在发送前用`LoadVideoTask`再次核对永久线路，账号ID相同但Key、地址、代理或协议设置变化仍拒绝；缺少SQL/主体/持久额度端口或请求取消也不发送。只读定位和复核不申请新资金，不要求新生成准入可用。实际创建的资金预留/绑定、终态恢复、运行时非单位倍率和unknown自动核实仍待接线验收，原503资金门继续生效。旧记录缺失原始归属时不补猜；混合旧版本媒体资金模式未经支持，升级须排空并安装迁移334，应用回滚保留永久身份表/约束。该基础不涉及真实上游采购价。

配置不代表生产已开放。升级/回滚须按[调度设计](project/monitor-driven-scheduling-design.md)排空旧视频/unknown成员并统一切换；保留原任务、额度和版本下限，禁止用删除槽位来解除阻塞。本地集成证据见[决策记录](project/DECISIONS.md)，生产多区域、排空和部署另行验收。

FIFO 的队列记录、head 判断、槽位申请、取消在同一 SQL 事务。取消保留永久身份；Live 转移锁定精确源成员并按 kind/id 稳定顺序锁预算，不先释放再申请。Live 账号迁移保留联合用户/Key 份额。SQL 槽位不会被 Redis TTL、启动清理或断连自动释放。

broker 先提交原始 payload 再发送，响应丢失或重启重放原 ID。主站过期且尚未发出的 issue 保存永久拒绝记录，HTTP 410 是可核实的未分配回执；只有收到该回执才允许后续新 ID。已分配但响应丢失的 issue 仍返回成功。未确认或过期续约不自动换租约。关闭沿用 drain→本地零占用回执→authority close。

当前 guard 检查完整预期成员 heartbeat、旧 Redis 身份 off、无旧身份连接、旧并发 namespace 排空。**这仍不足以证明因 TTL 丢失的旧请求已经停止，完整部署 inventory 与旧进程终止证明仍需接入。不得仅凭此 guard 开放生产 grant/流量。** 未使用账号区域独占，账号保持共享池。

已验证数据库取消先于迟到申请、跨 grant 同 ID 并发、事务回滚、FIFO、Live 精确转移/账号迁移/abort、broker 确认丢失与过期未发回执、旧凭据/成员/槽位 guard。完整真实应用多 Pod 端到端、可靠部署切换证明、资金与账号状态协调尚未完成，模型入口 503 保持。

迁移 281 只增表；已有永久身份不得删除。关闭入口、停止新接纳、保留已开始请求、结算/outbox 排空、显式关闭 grant 后才回滚。只回退二进制不能把已租出的槽位交回旧 Redis acquisition。

## 线路卡片与模型测试（开发分支已本地验证）

沿原入口`/admin/channel-operations`展示当前页账号的横向线路卡，包含参与状态、采购报价/来源、本地U/C、质量/身份、逐模型缓存与等待、业务记录及配置并发。聚合对照表移到「展开聚合对照与原诊断数据」，分页独立于折叠区并计入全部账号（含无用量账号），筛选/诊断入口保留，不新增第二套账号或调度逻辑。

1. 选时间、模型口径/模型及上游或账号；卡片参与状态筛选只作用于当前页，分页不会偷偷扩大批准来源。无模型筛选时各模型结果分别显示；不能把不同模型/档位的缓存率平均成一个通过结论。首文本均值只消费对应HTTP/WS版本与来源的有样本观测；旧口径、未知协议或零样本保持未知，不因数值为正就当有效测速。
2. 鹈鹕卡直接展示**当次冻结的被测模型、推理强度、分组、最终作答账号、前序失败尝试与执行时间**。当前计划改名不改历史模型；未知模型不猜补。最近执行失败与旧成功作品并列，成功生成不是模型身份认证。
3. 作品沿原管理员结果接口按需读取，校验结果ID/账号/组/模型/强度后用原`PelicanShowcaseCard`/`PelicanArtworkPreview`隔离渲染；加载页面不执行新的模型测试，来源不符不显示作品，可显式重读恢复。作品/详情不向下游泄漏采购身份。
4. 「价格与手动填写」打开原账号编辑器，手工U和限期适用声明保持原合同；「自动查询授权」打开原New API配置。卡内只读倍率组件无探测按钮，不因浏览面板触发供应商调用。保存后重新读取快照；打开编辑器仍须完整管理员权限。
5. 本人价与价目表分开；来源缺失/旧快照不当已确认，New API自动读取说明见[钱包与分组查询](new-api-upstream-probe.md)。倍率变新不能让质量/身份一起变绿，原会话粘性与人工限制不变。

新快照`model_tests`是只读section：`version=1/source=persisted_pelican_group_test_frozen_model`，只含当前页账号、指定窗口内的冻结请求模型与最终归属；每页最多100个账号×组×模型×effort结果组合，`total`单列，超限不称全覆盖。模型过滤仅支持已记录请求模型（本接口`public`口径），选择计费或映射模型时显示口径不适用，不借计划当前值。原质量轮次的模型口径另有合同，二者不互借。

缺失表/单section查询失败只撤该section，不把其他业务数据变成零；旧服务缺字段、未来版本、无样本和错误与通过分开。连通性、独立指纹和定向缓存的完整测试结论尚未由此投影读取，直接显示待核；它们和完整受管产品自动维护仍属原D3/D5/D7父验收，不由本卡片完成。

本轮无新schema。回退恢复前一应用仍可读取账号/用量/测试原表；旧程序忽略section但也恢复旧报价来源风险。生产未发布；中英1440/390px浏览器验证用本地API夹具，SQL及管理员HTTP另有真实隔离PG证据，不冒充生产数据路径。

## 产品价格与启用影响检查

1. 按产品/销售分组名称搜索并选择；也可检查已停用分组，检查不会恢复销售。列表每批最多100个匹配项，更多结果通过名称搜索缩小范围。
2. 点击「检查启用影响」。利润门关闭时按保存参数模拟开启，已开启时重读当前参数；不保存开关、不改关系、不发送付费探测。响应禁止缓存。
3. 先看「全部排除 / 价格边界保留 / 无检查账号」，再展开账号原因。最低用户覆盖价可能比默认售价更严格，界面独立显示其结果；上游真实网络、模型或缓存合格并不由本检查认证。

| 口径 | 来源与用途 |
| --- | --- |
| 准入 U | 保存账号倍率或当前有效上游同步证据；原 `PreviewProfitAdmission` 用于价格、采购范围/桶和来源边界 |
| 估算 C | 保存 `extra.cost_multiplier`；缺失时默认0.1，非法值明确提示回退；只作报表估算，不替代U，不是精确采购成本 |
| 销售 D | 分组默认价乘当前高峰因子；同时读取全部有效用户覆盖并计算最低D；不返回用户身份或覆盖明细 |
| 价格阈值 | 原服务按D、利润边际/安全缓冲及epsilon计算；前端只展示，不重算另一套公式 |

例如U=1、C=0.1、D=0.2时，即使报表估算盈利，启用价格门仍会排除该账号。明确0保留为0；缺失或过期U显示未知/证据失效，不借用C补齐。

`GET /api/v1/admin/upstream-procurement/products/:id/impact`仅完整管理员可读。产品、账号、采购目录、来源和覆盖价从同一只读SQL快照获取，时效按读取结束的时间核对。当前关联与批准来源去重合并最多1000个账号，超过时明确返回未完成，不偷偷截断；价格检查仍只纳入已关联、已启用且允许调度者，不把未关联来源写入价格候选。它不模拟临时冷却、模型/精确协议范围、健康、额度或实时槽位；高级范围诊断仍在原采购目录面板内。结果是标明时间的快照，配置变更或证据过期后需重新检查。

失败不显示旧通过，产品选择保留并可重试；产品删除、权限不足、无候选和过大范围分开提示。后台不向下游展示上游账号/来源信息。无数据库迁移；回退应用保留原有策略和关系。当前为开发分支本地交付，生产启用另验。

### 产品证据模板：先观测，再收紧要求

在原「分组管理 → 编辑分组 → 利润控制 → 采购范围与来源」中，选择「批准来源 + 当前答题 + 最新可用（v1）」并明确选择至少一个批准来源分组。模板同时设置原答题与可用状态要求；固定模板下不能单独关闭这些要求或退回无限制来源。它不启动检测、打开利润门、创建产品关联或认证模型身份/缓存质量。

先在原质量/共享观察入口配置检测并取得对应模型、协议和线路的当前证据。编辑已有产品时，可在本表单展开「保存前预演本策略草稿（只读）」，核对尚未保存的模板、采购边界、来源及默认售价/利润参数；渠道运维的普通精确预演仍检查已保存策略，不能用其旧通过代替新草稿。保存到已开启采购门的产品后，缺失或过期的必需证据会阻止新请求及已有会话后续生成；单纯选择模板不会补出通过结论，也不会为旧证据续期。

「自定义参数（v1）」明确解锁各项设置，切换本身保留原参数，需另行修改才会改变要求。已有策略默认「保留现有独立设置」，普通编辑不会静默升级；模板版本随配置固定保存。保存遇到409时保留草稿并显示最新模板，读取最新并明确核对后再保存，不自动重放。未知模板或版本保持只读并提示核对，不能当成关闭保护。

本地开发已实现v7合同和原保存/读回；原价格范围、采购桶、原生账号保护和发送前终检继续生效。无数据库迁移或检测/关联写入。生产尚未更新；回退到不理解v7的旧程序前须先停接排空该产品，保留配置与历史。

### 保存前预演采购策略草稿

1. 在已有产品的采购策略中改好范围、模板和批准来源，展开「保存前预演本策略草稿（只读）」。产品固定为当前编辑对象，目录只读；不会保存目录或分组，也不发起供应商检测。
2. 填写账号、公开模型与实际模型、协议、服务档和推理范围。原分组编辑入口同时模拟未保存的采购策略、默认销售倍率、利润开关、最低利润率和安全垫；百分比转换与原保存相同。高峰设置、订阅类型、平台、模型限制及其他设置仍采用同一快照的已保存值，不属于完整分组草稿预演或用户专属售价报价。修改平台后须先保存平台，再重新读取和预演。
3. 点击查询或在本预演输入框按 Enter，分别查看原价格、账号保护、必需答题和最新可用门。结果明确标注「基于保存修订 → 假设策略修订，尚未保存」，并回显模拟销售倍率、利润率及安全垫；草稿利润开关开启/关闭与已保存状态分列，关闭后已有策略的编辑和预演仍可见。原策略通过、新草稿缺证据时仍显示待验，不能沿用旧绿。来源不完整不查询，不退回全池；没有完整资格或实时容量保证。
4. 修改策略、售价、利润开关/参数或请求范围立即撤下旧结果；约30秒或原证据更早到期后转为待确认，不自动出站或重放查询。遇到409沿原表单读取最新配置，保留范围和请求输入，明确核对后重新预演；403、读取失败或响应不匹配均不显示旧通过。预演不提交外层分组表单；原渠道运维页仍支持输入框和查询按钮按 Enter，每次只触发一次只读预演。
旧接口仅提交采购策略草稿时仍采用原v1回执，其他参数全部使用保存值；只有显式完整提交联合利润草稿才使用v2回执，混合、缺失或参数不一致不显示通过。

5. 预演通过也不保存。最终更新仍使用原分组保存及独立版本检查；预演使用的假设修订不是授权或写入凭据。尚无产品编号的新建分组不提供此入口，完整接入/启用向导仍按原任务推进。

### 高级精确范围预演：价格通过不等于账号可调度

在同页展开「采购目录与范围归类」，填写账号、请求模型、实际模型/协议/档位，并选填产品分组后点击「查询当前范围归类」。该入口仅查询本地证据，不访问上游或消耗检测额度；它与上面的全产品价格影响检查用途不同。

- 先分别看「采购限制」「账号原生保护快照」「答题质量门」「最新可用状态门」，再看「已评估配置门交集」。采购价格通过，但账号手动停调、处于错误状态、性能/AI运维暂停、过期、过载、限流、冷却或原生额度用尽时，交集仍拒绝，不会自动解除任何保护。
- 账号保护沿用实际调度的判断和优先级；数据库读取时钟统一核对有效期与固定/滚动额度窗口，性能和AI保护也在同一只读快照读取。这里不读取并发占用或认证母账号/共享容量，不保证当前能取得槽位。
- 保护快照最长30秒，已知更早的到期、冷却恢复或配额周期边界会缩短期限。到期只变成「未核对或已到期」，不是自动恢复；再次点击预演读取当前状态。修改请求范围会清除旧结果，读取失败保留输入供重试。
- 价格快照也有独立期限：最长30秒，倍率快照、实际采用的供应商/手工适用声明可能提前到期；启用高峰倍率时，采购或销售侧下一本地分钟/时区切换也会保守结束快照。期限只约束这次读取，不保证期间配置不变，更不替代发送前终检。
- 价格快照或必需门先到期，价格/整体结论分别转为待确认；仍有效的账号保护独立显示。刷新只读取原证据，不延长上游声明或自动重做付费检测；原证据恢复后重新预演才显示新结论。
- 当前v4在同一次核对中返回逐门清单，分别显示「价格与批准来源」「账号原生保护」以及明确要求的「当前答题质量」「最新可用状态」的徽标、原因和期限。多项不满足会一起展示，不只返回第一个阻断；没有要求的检测不列为必需门。整体仍按明确失败优先，数值和期限由同一清单汇总。
- 每项按自己的期限变为待确认；任何必需项先到期，整体也回到待重新预演，不从剩余的部分结论重新推断整体。当前界面的清单是核对快照，不是可发送请求的授权。
- 旧交集v3响应保留其已核对的账号保护、价格期限与原交集，并提示缺少逐项清单，不补造门状态；交集v1/v2缺少相应检查，整体及价格期限继续保持未知。缺字段不补通过，未知版本、混合合同、重复/缺失/乱序门、矛盾计数/原因或期限拒显并可重试。
- 此结论仍不是完整产品资格：模型身份、严格高缓存、其他能力、人工/父账号约束与实时容量不能由价格或上述快照替代；原调度和发送前终检继续生效。预演不保存模式/关联/计划、恢复停调或发送付费请求，响应禁止缓存。

新增供给尚未关联销售产品时，完整管理员可在同一高级表单填写产品后，明确勾选「评估批准来源中的候选」。结果分列“已关联/尚未关联”与批准来源结论，继续复用原价格、账号保护、答题和可用状态门；不会为了计算而临时添加产品关联。未勾选时仍检查当前关联，未关联账号继续被拒绝。

候选只认可产品v6策略明确选择的来源分组：未选择或读取失效为待确认，明确空列表或账号已不在来源内为不通过。旧版原池限制、普通账号库存和单个账号ID列表不会代替批准来源。来源与产品、账号、质量/可用证据由同一个只读SQL快照读取；本次来源结论最多30秒后撤下，相关价格或证据可以更早到期。刷新不发起检测，候选通过也不等于模型身份/严格缓存/完整资格或发送授权。

接口仍为`POST /api/v1/admin/upstream-procurement/preview`，显式增加`evaluate_candidate:true`且必须有`product_group_id`；原命令与显式false保持原语义。只有候选返回的产品投影为version2并带`candidate.in_product`及`candidate.source_state`，原产品投影继续version1；二者的`evaluated_gates`仍沿原v4合同。旧服务、混合版本或矛盾元数据不显示通过；输入/模式变化撤下旧结果，403/503保留草稿供明确重试，不自动改为原模式。该读取不会建立关系、规则、计量、租约或outbox，不授予观察员/受限管理员额外库存权限。完整产品资格和自动关联仍按原D4.3继续实施。

无schema变更；回退应用保留已有账号保护、计划、证据和产品配置。开发分支的本地验证不表示生产已加载。

### 交给程序管理前的规则与预算检查

产品影响检查增加可选的「模拟新增检测」：保持「仅检查已保存规则」时行为不变；选择已有的观察型答题预设后，按**批准来源分组与明确账号限制的交集**，模拟每账号新增一条计划。选择器只列已启用的原生账号通道答题/随机题观察预设，不接受移组、停调、BPS或导入2FA规则；「管理质量预设」仍进入原质量入口，不另造模板系统。

结果分列两项结论，避免把预算内误解为可以新增：

- **原观察计划冲突：** 按同一快照检查全部批准账号，包括未关联产品或暂时停调的账号。已有观察计划时列出账号名称、原计划编号和启用/暂停状态；BPS观察计划也占用同一个观察规则位置，暂停不释放位置。普通检测、隔离等其他动作规则不误报冲突。超过20项分页查看，沿「查看账号质量规则」进入原入口处理；预演不替换、复用、接管或跳过旧计划。无冲突只说明核对时的位置情况，不预留位置或授予下发权限。来源为空/未知或旧版v1响应未提供此检查时明确显示未核对，缺字段不补通过。
- **预算下界：** 来源未确认 / 来源为空 / 预算未开启 / 已证明超限 / 已知下界内但覆盖不完整；展示当前全局、新增、变更后调用下界和普通日容量。即使存在计划冲突，仍按完整新增假设测算，不去重省钱。未关联产品或暂时停调的批准账号仍需要恢复检测容量，不因停调漏算。多模型×样本及LLM/JEV判题复用原编译器；预设更新时间、来源策略修订、预算修订和下一完整UTC日窗口同时显示。

预演不写计划、管理模式、产品关系、额度或历史，不启动检测；通过容量检查也不证明模型身份、质量或完整产品资格。来源未知不回退原池或全站；未估算项、站点/共享Key峰值、Token与检测时效不作承诺。预设/产品选择变化清除旧结果并丢弃迟到响应；失败可原位重试。其他窗口修改了预设时可用「刷新预设」重新读取，失效选项被清除。接口复用原只读GET的可选`monitoring_preset_id`，不携提示词、参考答案或凭据；没有schema迁移，旧服务器缺少配方结果时显示未完成。

在同一结果卡的「首次下发观察计划」中，完整管理员可以明确确认一次性新增：

1. 先核对批准来源账号数、预设、调用下界和未知覆盖。只有产品启用、全部批准账号均无观察计划、预算保护已开启且已知下界未超限时，才提供确认勾选；未知来源、空来源或旧版响应不补写权限。
2. 勾选费用说明，再点击「确认下发观察计划」。本次复核最多有效2分钟，客户端从请求开始计时，迟到响应不延长时间。期间改预设、来源、预算或计划会在服务端重新核对时拒绝；管理员更换产品/预设或重新预演后要重新勾选。
3. 保存复用原账号级观察计划，写入前取得原共享预算锁并重读，再按原唯一约束批量新增、沿原覆盖编译器终检；有冲突或任一行失败则整批回滚。并发管理员/不同产品争抢同账号时只允许一批成功，另一批返回409；不跳过、接管或合并旧计划。
4. 成功回包后，页面独立GET逐条核对账号、原计划编号和启用状态，核实后才显示已保存；重新打开也会读到原观察计划冲突，避免重复付费。通信中断显示「结果未确认」，保存成功但读回失败单独提示「读回未核实」；先沿链接检查「账号质量」中的现存计划，再重新预演，旧确认不自动重放。

未关联产品或暂时停调的批准账号也会得到已启用的观察计划，按原周期检测；这不会恢复业务调度、改变产品关系或开启自动接管。`POST /api/v1/admin/upstream-procurement/products/:id/monitoring-recipe`只接受原GET的预设ID、复核时间和指纹，响应不含题目/答案/凭据，用户和观察员不开放此入口。新增计划可被原执行器读取、领取及完成，不新增执行器或计费逻辑。多产品策略已确定为模型并集、更严格周期、超预算阻断；共享计划的持久归属和确认保存见下方独立入口；首次下发仍不认领旧计划，不跟踪后续新增来源账号或改写既有计划。无schema迁移；回退应用保留已创建原生计划，回滚部署不会自动删除或暂停这些计划，管理员需在原质量入口明确处理。

同一产品影响卡的「多产品共享观察计划」用于统一管理不同产品共同需要的观察计划：

1. 打开后先读取整份已保存参与清单及修订，读取失败时禁止编辑/预演；「重新读取已保存配置」会用当前保存内容替换页面草稿。一次保存替换全部参与产品，不是追加，须保留仍需检测的其他产品。最多20个不重复产品，每个选择原观察预设；搜索分页不删除已选产品。
2. 点击预演，核对批准来源、去重账号、模型并集及覆盖全部要求时刻的原生Cron。配置/时区不相容、来源未知、预算超限分别展示。新版本按已受管计划替换需求，不重复累计；减少需求可显示负差额。已有手工、模板、首次下发和旧暂停计划不自动认领，冲突整批阻断。
3. 「整批变更结论」列出新增、更新、保留、暂停/交还及冲突。核对完整清单和费用后勾选，再明确保存。页面从请求开始30秒撤回确认，服务端2分钟指纹绑定已保存修订、预设、来源及预算；并发修改、运行中、内容漂移、缺失计划及任一行失败均整批回滚。新旧受管账号合计最多1000个，超限不返回部分方案。
4. 保存成功后另一次原GET核对修订、完整参与清单、账号/计划编号、启用状态与归属，核实后才显示成功。重新打开恢复完整清单。409、丢失回包或读回失败撤下旧确认并禁止重放，先点击「重新读取已保存配置」查看实际状态，再重新预演；不盲目重复付费。
5. 移除产品只移除该产品需求，仍被其他产品要求的账号继续共用原计划；失去全部需求的受管计划暂停，历史和归属保留，重新加入可复用编号。清空参与清单默认暂停全部受管计划；如同时勾选「解除共享归属」，先暂停再交还手动管理。缺失/漂移/运行中的计划仍拒绝更改，不以删除归属掩盖未知状态。

保存只维护共享参与与原生观察计划，不调用供应商、不改产品关联/停调状态，不授予模型身份、缓存或完整产品资格。已有原执行器按周期执行并沿原预算计量；默认仍需手动重新预演；明确开启下述持续维护后，由原调度器追踪已保存产品的来源与预设变化。受管计划的原手工编辑/删除及归属操作被拒绝，须在此先暂停并解除共享归属。无schema迁移；回退保留配置和原计划，使用不理解共享归属的旧程序前先完成上述解除步骤，避免绕过保护。

账号的原「定时测试」新增/编辑表单，以及「质量运维 → 检测工作台 → 编辑规则」提供「变更前检查检测预算 → 预演预算」。质量规则新建时，管理员手动选择单个账号即可预演；批量编辑、分组模板、预设及观察员不显示单计划可行结论。无需记预算修订：点击后先读取当前共享配置，再用同一SQL快照比较当前已保存库存与应用本计划草稿后的调用下界，显示当前、差额、变更后及普通检测容量；编辑替换原计划，不重复累加，停用/减少周期需求可显示负差额。周期或配置变更会立即清除旧结果；409、权限/读取失败和旧服务器不支持时保留草稿、不显示旧通过，重试重新读取。正常保存仍由原事务内复核，预演不预留额度或认证完整覆盖。

此入口只模拟明确账号计划：质量规则直接复用保存时的规范化参数，探针不携带判题或题目、多模型/并行样本及外部判题沿原原生编译器计数，不另算一套需求。统计窗口是读取时刻之后的下一个完整UTC日，不是未来滑动24小时；同一个原生检测规则的复测/恢复及插件计量仍依原执行器。Token仅在上游实际回传后计量，不事前猜测；重试、站点/共享Key峰值、未知通道和完整产品自动检测配方不包含在差额，不将此处「已知下界可容纳」当作可自动接管产品。无数据库迁移、出站或计划写入；回退旧程序仍保留原计划和共享预算，缺少的草稿结果会显示未完成而非0。

同一个「检查启用影响」还会读取下列内容，无需另填规则或账号 ID：

1. **关联写入 / 保留归属**：显示仍会移出本产品的启用规则，以及仍保存本产品恢复归属的规则。账号已移出、计划已暂停也不隐藏；它们不等于可立即恢复，需从「查看质量规则与归属」进入原拥有者预览后处理。
2. **其他账号保护**：停调、模型冷却、BPS、连通性恢复等继续保留，不混成产品成员关系冲突。未知动作或不可解释的保存状态单列待核对，不自动清除。
3. **判题依赖**：标出使用本产品作为普通判题来源的相关规则；被测成员被隔离可能使判题库存耗尽。不同分组或地址仍不证明独立参考来源。
4. **共享检测预算**：显示全站已保存计划的调用量下界、预算版本、UTC窗口和原编译器原因。未启用、已知下界超限、仍有未估算需求分别展示；下界可容纳不等于完整周期、Token成本或实际空闲容量可保证。没有新增检测、预算预留或新产品增量估算。

「供应来源与当前关联」按原采购策略v6的批准来源分组及账号名单取交集，按名称列出分组与账号，独立显示已关联/尚未关联、是否在批准来源交集和原生状态/开关。未配置/沿用原池、明确空交集、来源失效分别显示；失效时计数未知，不回退全站账号。已有成员即使不在批准来源仍保留检查。来源许可不认证健康、价格或模型质量，未关联来源不自动加入产品；原有普通/专用账号不因盘点被纳入。

来源有效时，规则检查扩展到批准交集中尚未关联的账号；同时保持当前成员与明确移出/恢复本产品的保存目标。来源未确认或原池模式只检查原范围，并明确标注未扩展；不是完整依赖图或所有控制器审计。规则最多读取1000条，超出时计数为已读下界、完整冲突范围未知；账号与规则独立分页。未知、旧服务器缺字段、预算读取失败均不补成通过或零；失败后保留产品选择并可重试。

同一面板的「其他自动写入者与保存状态」补查原执行器的四类分组写入，不再把“质量规则没有冲突”当作整个产品没有关联竞争：

| 写入者 | 管理员需要知道的影响 |
| --- | --- |
| 403自动移组 | 可替换或清空账号全部关联；保留原账号类型、授权与有效目标校验。显式目标为0表示移出全部，不当作未知或未配置 |
| OAuth降级 | 当前启用策略可能移出本产品或限制账号；已执行历史不是永久排除表，不阻止人工重新关联 |
| Astra调度与恢复 | 同时核对当前配置和保存的关联快照；关闭开关不等于解除原恢复归属。账号/模型模式残留的分组选择仅是元数据，不误报成分组拥有者 |
| 2FA准入隔离 | 使用账号登记与对应计划，而非后来修改的全站默认值；暂停后仍可能恢复，登记/计划不匹配为待核对 |

结论分成「关联冲突」「账号保护」「仅历史 / 当前不适用」「待核对」，展开才显示逐账号原因和原配置入口。计数按写入者记录，不是独立账号数或请求失败次数；同账号可以有多个控制，不与质量计划计数相加。启用配置只代表潜在动作，触发条件与实时运行另判；冲突和未知都不是自动停掉原保护的许可。旧服务器缺此字段显示未检查，未来/矛盾合同清除结论后允许重试，不显示为0或通过。

其他写入者从同一只读快照检查当前/批准供应以及明确指向本产品的配置、保存归属和Astra配置目标；外部目标账号仅供冲突检查，不加入批准来源或价格候选。合并最多1000账号，超出整次返回范围过大，不截断为成功；与质量规则、来源列表独立分页。未知配置可能隐藏额外目标，覆盖保持未完整；不宣称覆盖未知外部程序或未来导入账号。

价格和写入者检查本身仍为只读，**不启用产品或自动关联**。同入口的审核授权现可独立预览并确认现有关联归属；审核不是自动执行，增量预算、统一资格、自动差量和完整三步仍按主设计推进。新摘要与价格结果从同一只读SQL快照读取，保留所有原限制和恢复记录；检查自身不做数据迁移、不出站、不改生产设置。回退应用保留全部原数据和执行器，但旧界面将缺少新增写入者提示，不是等价的接管检查。

关联归属的数据基础已在原关系表中接入，不需要管理员另建账号清单或填写新ID。旧关联保持人工状态；正常编辑保留未移出关系的归属，普通移出只删除当前关系，人工重新加入不会继承被删除的程序归属。质量隔离/恢复和Astra恢复携带原归属；同一关联已易主时，Astra保留冲突而不覆盖。复制到新产品则建立新的人工关系，不复制旧产品拥有者。此基础包含可空归属列的迁移，但不启用程序管理，本轮也未在生产执行迁移。以后受管产品回退到旧二进制前仍须先停接/排空；保留列和原数据，不等于旧版本理解或执行归属约束。

配置入口也可从左侧功能搜索或 `Ctrl+K` 找到：搜索「检测预算 / 共享检测预算」直达网关设置的「上游渠道声明自动探测」及原预算卡；搜索「缓存率 / 缓存命中率 / 缓存读取占比」直达原使用记录卡。英文支持 `shared probe budget`、`monitoring budget`、`cache rate` 和 `cache hit rate`。搜索只索引当前可见的管理设置入口，不向无此入口者暴露隐藏页面；别名不改变计费缓存与原始缓存的口径。

### 审核现有关联，不开启自动执行

1. 选择销售产品，先点击「刷新审核状态」，确认当前为手动或审核，以及本轮认领、保留归属、人工关联各自数量。读取失败为未确认，不补成手动或0；旧产品默认手动、修订0，不自动认领。
2. 点击「检查激活影响」，在「供应来源与当前关联」展开账号，仅勾选已有且在明确批准来源交集中的关系。尚未关联、来源未知或未批准的账号不提供认领入口；该步不认证真实模型、缓存、质量、健康或容量。
3. 点击「预览所选」，逐项查看当前归属、阻止认领的原因和继续有效的保护。质量/原生关联写入冲突、未解释保存状态、未知配置或覆盖不全不允许直接抢占；原账号停调、模型限制、检测计划和利润门不被审核解除。
4. 预览有效2分钟。勾选确认说明后再点击「确认审核归属」，服务器锁后重读配置/关系/授权，以内容指纹、修订和数据库时钟校验。变化、过期或并发确认返回409，保留选择但清除旧预览与确认，须重新预览；不强制覆盖或清历史。
5. 保存后独立读回状态并刷新原影响结果。写入成功即废弃并取消所有写前影响检查，迟到响应不覆盖新状态；读回失败清除旧结论、不显示已生效，可原位刷新核对，避免重复认领。只有当前审核修订明确认领的关系计入本轮，先前修订为保留归属，不把所有历史拥有者都显示为当前受管。
6. 「回到手动」仅结束当前审核修订，保留原关系及归属，不删除或恢复账号。审核状态读取与回手动不依赖损坏的价格目录、来源库存或大清单；未知未来管理合同保持拒绝覆写。普通移出后手工重加仍是新的人工关系，不继承旧拥有者或建立永久排除。

本阶段只提供手动/审核，不接受automatic；不会新增/撤销关联、改检测预算/计划或发出付费请求。原生保护仍可执行，后续自动协调器须每次重验保护与精确scope。数据库仍沿用原关系配置修订触发器，认领会推进对应账号的配置修订，使旧预览失效；不改凭据、额度、状态或价格。正常请求时间、运行时用量刷新及无关界面设置不导致审核指纹抖动。迁移350仅加可空审核授权列，不认领旧数据；生产未执行。回退保留授权和归属，运行旧二进制的兼容性另行验收。

### 共享计划的持续维护

先在共享观察面板保存完整产品/预设清单，再勾选费用与持续变更授权，点击「开启持续维护」。该开关只维护已保存的参与产品及其批准来源；不自动认领普通/专用账号，不自动接管手工规则，也不开放产品调度资格。未保存编辑不生效；手动保存整份清单会关闭持续维护，按需要再次明确开启。

原调度器每分钟在读取到期计划前核对一次：批准账号新增/移出、产品停用/恢复、预设模型/周期变动时，复用原预算保护与计划写入，合并共享模型及执行时刻。失去全部需求的自有计划暂停，来源返回时复用原编号/历史。产品停用或软删除停止贡献需求，保留参与记录；来源未知、缺预设、内容漂移、计划运行中、不相容或预算不足则整批暂缓，恢复后重试。多实例共用原预算锁，不重复新增；无变化不重复写计划和归属。

面板用状态、原因和新增/更新/暂停数展示最近结论变化；这个时间不是巡检心跳，也不代表模型验真通过。写入异常会回滚整批计划后记录失败结论，界面不显示数据库或上游秘密。点击「关闭持续维护」只撤回后续自动维护授权，已有检测继续由原执行器运行。开关使用保存修订防并发覆盖，并独立读回确认；409或通信结果未知时先重新读取，禁止重放旧确认。完整管理员可操作，观察员和受限管理员保持禁止。

遇到持续维护暂缓时，先看结构化原因和对应的原配置入口：预算问题进入共享检测预算，预设/模型/时区问题进入质量规则与预设，来源/产品范围问题进入原分组。已受管计划若缺失、内容变化或正在运行，面板按账号编号、原计划编号和具体结论列出，每页20条，可跳到原质量计划入口；这是本次独立读取的计划检查，不是最近维护结论的巡检时间，也不包含尚未受管的新来源或所有阻断原因。重新读取不会写计划、重放保存或发起检测，运行中的计划结束后由原调度器重试。

保存或切换维护开关后，若发生409、丢回包、坏回执或独立读回失败，旧模式、修订和计划结论会撤下，显示“尚未重新核实”；当前草稿保留，编辑与再次保存暂不可用。先点击「重新读取已保存配置」，取得实际状态后再决定是否修改，不把原来的“维护中”当作本次写入成功。

该开发功能尚未上线；不改变原检测实际usage预算、未知缓存口径、倍率门、会话黏性或共享Key限制。回退到不理解共享归属的旧应用前，须先关闭维护并按共享面板暂停/交还计划，保留历史。

## 用量、质量与错误观察

### 检测轮次如何看判题问题

「质量运维」`/admin/account-quality`打开轮次详情，按**答题结果→本轮判题依赖→账号动作**依次看：

- 普通判题池显示“已取得判题结论 / 判题受阻 / 判题答复不确定”，并列出筛选后候选数、槽位检查、未取得槽位、适配器调用、未取得合规结论及本地预算延期数。无库存读取是“—”，成功读完但无候选是0；本轮计数不冒充当前容量或物理计费请求。
- 判题组缺失/停用、模型未允许、库存读取失败、并发协调故障、全忙、无候选、调用失败、无合规结论、预算延期与取消分别解释。判题系统受阻不是被测模型答错，也不据此恢复账号。
- 本规则移组动作包含判题组时显示依赖风险；共用这些隔离规则可能耗尽判题成员。使用不受这些动作影响、支持判题模型的来源；不同账号/地址/分组仍不证明来源独立，模型身份无独立基线继续未知。
- 检测规则归账号，不归产品成员关系。正常移出产品组不会删除原检测计划；原账号开关、冷却、预算和运行租约继续约束复测。恢复冲突沿原拥有者面板处理，不把判题通过当作已成功恢复。
- 旧记录、未知合同和Jev独立通道不补普通池计数，不回填历史；当前诊断不代表独立参考池、完整依赖图或产品资格已完成。
- 旧记录即使保存了传输`success`，只要判题明确`unknown`，答题徽标仍为中性“判题未完成/不确定”，不把传输成功误显示为答题通过。

检测结果与计划的读取按观察员当前授权的账号分组过滤，越权详情不透露存在性；写入在账号锁后重验关系，授权被并发移除时回滚。完整管理员保持原权限。无新增检测调用、数据库迁移或生产配置变更。

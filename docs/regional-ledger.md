# 区域资金账本与请求恢复

`internal/regional/ledger` 提供主站和区域 PostgreSQL 的事务核心，`ProvideRegionalMetering`复用现有运行时接入预算、不可变价目和后台控制。单位倍率视频创建及原节点查询/终态结算已接通；配置、已注册入口与未支持范围见[运行时约定](regional-runtime-budget.md)，完整任务验收见[统一设计](project/monitor-driven-scheduling-design.md)。本地验证不代表生产已开放。

## 资金与精度

主站 `Primary.Issue` 在同一事务中从用户可花费余额扣除额度并保存永久租约身份。重复相同租约不会再扣款；同 ID 不同用户、区域、金额或时间拒绝。多个区域争抢同一余额通过用户行锁和余额条件更新协调。租约金额用 nano USD 整数，要求为 10 的整数倍以对齐既有 NUMERIC(20,8)。所有 SQL 金额通过精确十进制字符串传入，不经 float64；超范围和不合法精度拒绝。时间要求微秒精度以保留 PostgreSQL 的幂等身份。

租约只是区域获准花费的额度。`PrimaryRequests.Reserve`与`Primary.Issue`共用SQL资金和预算权威，避免主站请求与区域grant分别扩大余额；API Key、订阅、账号和用户平台额度由`RegionalBudgetScope`在原事务内锁定预留。启用须具备切换与旧用量导入证据，缺少权威时拒绝，不回退旧异步余额缓存；完整多Pod和生产切换仍属独立验收。

## 区域请求与恢复

区域使用独立本地 PostgreSQL；所有 Pod 共享同一本地账本。`Install` 必须只接收受认证主站发放的租约，同 ID 不能更改。`Reserve` 持久保存请求身份、payload 摘要、模型、定价版本和保守费用上限；`spent + reserved <= granted` 通过租约行锁与数据库约束保证。数据库故障直接拒绝。

视频新建在主/区域两种账本的`Reserve`和`Start`事务内复验本地SQL售价与主体，不能借旧鉴权快照绕过改价或停调；预留拒绝时永久身份与资金同事务回滚。`Start`在发送上游前提交，重复启动拒绝；区域租约到期或进入draining后不可启动。确认仍为reserved且在状态转换前复验拒绝才返回`ErrStartRejected`，适配器调用`CancelBeforeStart`退款。其他Start错误（含提交确认丢失）保留预留且不发送，不凭本进程零出站推测数据库未提交。

`CancelBeforeStart`仅允许未启动请求退款；视频收到明确供应商拒绝时，`RejectVideoTask`还可在同一事务证明原永久身份尚未绑定后退还started预留，绑定/退款竞争由原行锁串行化。未知结果、5xx、缺任务ID或崩溃遗留started请求继续占用全部最大值，不因TTL、重启或重试自动归还。无ID unknown的自动核实仍需供应商关联查询契约，不猜测释放。

`Complete` 只接受与预留身份、价格版本、模型一致且不超过预留的最终费用，在同一事务中更新 spent、释放预留、写入 outbox。未知用量和超上限费用不得伪造成功或释放占用。接纳于租约有效期内的请求允许到期后完成。用量包含原始 token 计数用于对账，不保存提示词、输出或凭证。

## 结算与关闭

`Primary.Settle` 强制要求定价/归属验证回调，缺失验证器拒绝。验证、canonical usage log 写入（由验证器负责）、租约 spent 和永久事件去重应属于同一主站事务。重试保留同 ID、同内容；同 ID 冲突拒绝，JSON 整数比较不经过 float64。

只有主站受认证确认同一完整事件后才能调用 `Acknowledge`。outbox 和请求记录永久保留用于去重；没有自动清理策略。`Drain` 序列化阻止新预留/启动，等待已启动请求完成；`Close` 要求无在途且全部 outbox 确认，产生带最终 spent 的关闭凭证。主站核对区域与 spent 后原子返还未花额度，重复关闭不重复返款。过期永远不能替代关闭凭证。

## 接线与发布边界

- 后台控制沿既有TLS1.3、CA与证书pin、固定区域和用户/Key/账号范围工作；视频查询转发使用独立mTLS监听，任务、额度和结算仍归原节点。
- 视频永久`VideoOrigin`、任务索引、创建时Price与事件保留在原SQL；跨区查询不创建新资金身份，不根据目录接管任务。三家适配器共用Reserve→Start→provider POST→Bind及原账本终态结算。
- 不可计量请求、非单位动态销售倍率及缺少财务凭证的查询继续明确拒绝；非单位/高峰精确合同、unknown自动核实和多peer仍待完成，不用部分验证关闭D2。
- 独立本地DB/Redis部署、备份、真实多Pod请求、配置传播和双方账单对账继续按统一设计验收；生产排空、迁移和部署需对应授权。

数据库迁移279建立原账本；后续资金/视频迁移沿原迁移器追加，333的零金额约束和334的永久视频身份须协调版本保留。回退应用不会自动返还已发租约；先停止新接纳、排空原任务及outbox并显式关闭grant，保留全部账本、身份和去重证据，禁止删除表、重置版本或直接把金额加回余额。
